# 太鼓の達人 曲当てクイズ

おに譜面と ★・BPM・最大コンボ数・ジャンル・初出作品を見て、曲名を当てるブラウザクイズです。
曲データは「太鼓の達人 譜面とか Wiki」（https://wikiwiki.jp/taiko-fumen/ ）から集めています。

## ファイル

| ファイル | 内容 |
| --- | --- |
| `index.html` | クイズ本体 |
| `online.js` | オンライン対戦（部屋コード）。Firebase Realtime Database を使う |
| `fumen-parse.js` | 譜面画像の読み取り処理と、譜面の描画処理 |
| `charts/` | 譜面データ（`tools/parse_charts.py` が譜面画像から作る）。クイズはこれを読み込んで譜面を描く |
| `data.js` | 曲データ（`tools/build_data.py` が自動で作る） |
| `start_server.bat` | 手元で遊ぶときのサーバー（YouTube の再生に必要） |
| `tools/` | Wiki からデータを集めるスクリプト |
| `../.github/workflows/taiko-quiz-update.yml` | 曲データを毎日自動で更新する GitHub Actions（リポジトリの一番上にある） |

## 手元で遊ぶ

`start_server.bat` をダブルクリックすると、ブラウザで `http://localhost:8000/index.html` が開きます。
（`index.html` を直接開くとクイズはできますが、正解時の曲は流れません）

## オンライン対戦（Firebase）

トップの「オンライン対戦」で部屋を作り、6文字の部屋コード（または招待リンク `?room=XXXXXX`）で友達が入ると、同じ問題で対戦できます（最大8人）。
通信は Firebase Realtime Database を使い、送るのは出題する譜面の番号・何問目か・各自の回答（正誤・時間）だけです。譜面は各自が `charts/` から読みます。

- 得点: 正解 100 点＋早さのボーナス（すぐ答えるほど多く、最大 100 点）。1問の制限時間（30〜180秒）はホストがロビーで決める
- 出題設定（★・ジャンル・作品・問題数・難易度）はホストのトップ画面の設定を使う。4択は全員同じ並び
- 全員が答えるか時間切れで答えを出し、ホストが「次の問題へ」で進める。ホストが抜けたら、残った人のうち最初に入った人が引き継ぐ
- 読み込み直しても URL の部屋コードで同じ部屋・同じ問題に戻る
- 難易度が おに のとき（ランダムマッチはいつも おに）: 曲の情報は最初は全部伏せ、制限時間の 2/15 ごと（60秒なら8秒ごと）に 情報（★・ジャンル・BPM・コンボ・初出年・収録）を1つずつ自動表示（開く順番は問題ごとにランダム、全員同じ）。「次の情報まで あと○秒」を表示。自分では開けない
  譜面は上の段から少しずつ表示（最初に 1/6、曲の情報が 1 つ開くたびに同時に 5/36 ずつ増え、6 つ目の収録作品で全部）。答えたら全部見える
- かんたん・ふつう・むずかしい（部屋のみ）: 曲の情報も譜面も最初から全部見える
- ランダムマッチ: 待ち部屋の一覧（`lobby/oni/<部屋コード>`）から古い順に入り、なければ待ち部屋を作る。2人そろうと10秒後に自動で開始（8人ならすぐ）。出題は おに・★8〜10・全ジャンル・海外以外の全作品・10問・1問60秒で固定。1人で待っている部屋は、もっと古い待ち部屋があればそちらに移る（同時に探し始めた2人をまとめる）

### 設定のしかた（最初の1回）

1. https://console.firebase.google.com/ でプロジェクトを作る（無料の Spark プラン）
2. 「構築 → Realtime Database」でデータベースを作る（場所はシンガポールなど。ロックモードで作成）
3. 「ルール」タブに `tools/firebase_rules.json` の中身を貼って公開する
4. 「構築 → Authentication」で「匿名」ログインを有効にする
5. 「プロジェクトの設定 → マイアプリ」でウェブアプリを追加し、表示される `firebaseConfig` を `online.js` の `FIREBASE_CONFIG = null` の `null` と置き換える（この値は公開してよいもの。安全はルールで守る）

`FIREBASE_CONFIG` が `null` の間は「オンライン対戦」ボタンは出ません。

### 手元での確認

`start_server.bat` で開き、`http://localhost:8000/?mock=1` を2つのタブで開くと、Firebase なしでタブ同士で対戦できます（localhost のときだけ）。

## 譜面画像の扱い

WIKIWIKI の利用ルールでは、他サイトから Wiki の画像を直接参照（img タグなど）することが禁止されています。
そのため、譜面画像はデータ作成時に一度だけダウンロードして譜面データ（`charts/`）に変換し、
サイトはこの譜面データだけを読み込みます。遊ぶ人のブラウザが Wiki の画像を読み込むことはありません。
なお、譜面とか Wiki の利用規約 第4条2項では、譜面画像を他のサービスで利用することについて、運営は権利を主張しないとされています。

## 曲データの自動更新（GitHub Actions）

リポジトリの一番上の `.github/workflows/taiko-quiz-update.yml` が毎日 3:00（日本時間）に `tools/update.py` を実行し、
変わったデータ（`data.js` と `tools/*.json`）をコミットします。コミットされると GitHub Pages にも反映されます。

1回の実行で行うこと:

1. おに★1〜10の一覧ページを取り直す（新曲・★・BPM・コンボ数の変更）
2. 初出ページ（AC16）を取り直す
3. 今も曲が追加される作品（ニジイロ現行・NS2・PTB・DF）の収録曲を取り直す。未取得の作品があればそれも取る
4. まだ取っていない曲ページを最大150件、取得日が古い曲ページを30件取る
5. 新しい譜面画像を最大300枚ダウンロードし、譜面データ（`charts/`）に変換する
6. `data.js` を作り直す

- Wiki に負荷をかけないよう、どの段階も約20秒に1ページのペースで取ります（1回あたり最大で数時間）
- 一覧の取得に失敗して曲数が大きく減ったときは、前の一覧のまま更新しません
- 途中で止まっても、進んだぶんはコミットされ、次の回に続きから取ります
- **Actions** タブの「曲データの自動更新」→「Run workflow」から手動でも実行でき、取得件数も変えられます

### 最初に上げる前に

全曲ぶんの曲ページ（約3,100件）を最初から取るには、20秒に1件で十数時間かかります。
手元で `tools/fetch_songs.bat` と `python tools/scrape_works.py` を最後まで動かしてから上げるのがおすすめです。
途中のまま上げても、Actions が毎日150件ずつ続きを取ります（全部そろうまで3週間ほど）。

### うまく動かないとき

- Actions のログに `429` が続く、または `403` で止まる場合は、Wiki 側で GitHub のサーバーからのアクセスが
  制限されている可能性があります。その場合は手元で `python tools/update.py` を実行し、結果をコミットしてください
- 取得件数は `MAX_FETCH`、取り直す件数は `REFRESH_OLDEST` で変えられます（手動実行の入力欄からも変更可）
